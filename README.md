# Akshatha Manjunath — projects & research journal

A hand-written static portfolio. No framework, no build step, no package
manager, no analytics, no cookies. Ten pages, one CSS cascade, about ten
kilobytes of progressive enhancement.

This machine has no Node, npm or Python, which is why there is no toolchain
here at all — see [Local preview](#local-preview).

## Local preview

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/serve.ps1
```

It binds the first free port from 4173 upward on `localhost` and prints the
URL. `System.Net.HttpListener` is allowed to register a `localhost` prefix
without administrator rights, which is why this works on a machine with no
runtimes installed.

Behaviour worth knowing:

- directory indexes resolve, so `/projects/` serves `projects/index.html`
- `/projects` (no slash) 301s to `/projects/`
- a missing path serves `404.html` **with a 404 status**
- path traversal outside the root is refused
- every response is `Cache-Control: no-store`, so edits show up on reload

There is no live-reload. Refresh the browser.

## Re-theming

Open `assets/css/tokens.css`. Everything descends from the block marked
`RAW PALETTE` — change those twelve values and the whole site follows,
including the chart series and the focus rings.

Two things do **not** follow the tokens, because they are external SVG files
referenced from CSS and cannot use `currentColor`:

| File | Hard-coded colours |
|---|---|
| `assets/motifs/jali-band.svg` | `#B7A98C` strokes, `#A98443` dots |
| `assets/motifs/kolam-rule.svg` | `#B7A98C` stroke, `#A98443` and `#9E6448` accents |
| `assets/img/monogram.svg` | `#36406B`, `#D3C8B1`, `#9E6448` |
| `assets/img/favicon.svg` | `#262E4E`, `#F7F3E9`, `#9E6448` |
| `assets/img/plates/*.svg` | the whole plate palette |

If you change the palette, edit those files too — they are plain SVG and take
a find-and-replace.

### The two ornament motifs

Per the brief, ornament is deliberately limited to two moments:

1. **Jali band** (`assets/motifs/jali-band.svg`) — a 24 px repeating
   eight-point star lattice. Used in exactly three places: under the home
   header rule (`index.html`), as the top edge of each case-study hero plate
   (`.case-figure > .jali-band`), and in the footer band on every page.
2. **Kolam rule** (`assets/motifs/kolam-rule.svg`) — one continuous loop
   stroke with ochre dots on the peaks and terracotta diamonds on the
   centreline. Used as the divider between major sections, in place of `<hr>`.

Adding a third motif is a decision, not a tweak: it will change how busy the
site feels. The `.jali-band` and `.kolam-rule` classes are the only hooks.

## Filling in the placeholders

**No project, paper or personal detail is invented on this site.** Where real
content has not been supplied yet, the page renders a marked placeholder
instead. There are two of them.

| Marker | Looks like | Means |
|---|---|---|
| `.slot` | a dashed box with a mono label such as `TO SUPPLY — 2 TO 4 PARAGRAPHS` | a block to replace wholesale. Delete the whole element, put your own HTML in its place |
| `.fill` | monospaced terracotta text on a dashed underline, e.g. `stack` | one field inside running prose or a table cell. Replace the span with the value |

Both are defined in `components.css` under `15. FILL-IN SLOTS`. Neither is a
templating feature — they are ordinary classes, so a finished page has none of
them left and nothing to clean up.

Some slots are labelled **Editor note** and are written for you rather than for
a reader. Those are instructions that explain the layout, and each one says so
in its label. Delete them as you finish the section they belong to.

Where the placeholders are:

| Page | What is still to be supplied |
|---|---|
| `index.html` | the "Currently" list, two project cards, one research entry, the "Why the long version" section, three figures in the Away strip, and an Editor note describing the site's state |
| `projects/index.html` | two slot entries and an Editor note |
| `research/index.html` | one slot entry and an Editor note |
| `projects/project-01/index.html` | the whole write-up. Title, lede, five spec rows, a callout, and a prompt inside each of the five sections, plus a measurements table with placeholder cells |
| `projects/project-02/index.html` | the same scaffold for the second slot |
| `research/research-01/index.html` | the whole write-up. Question, five spec rows, a finding callout, five section prompts, a dataset table and a references list |
| `about/index.html` | four bio sections, the "Based / Focus / Status" rows, the toolkit, and the page-head meta line |
| `away/index.html` | the three page-head figures, the chart, the milestone list, eight craft captions and the hike table |
| `contact/index.html` | email address and social links — see below |

The global items that no slot covers:

| What | Where |
|---|---|
| Email address | `contact/index.html`, the `mailto:` href and the `data-copy` attribute — currently `akshatha@example.com` (`example.com` is a reserved domain) |
| GitHub / LinkedIn | `contact/index.html`, `.link-list` — currently point at the platform home pages on purpose rather than inventing a profile that 404s |
| `Last updated` dates | the `.fill` fields on the home, About and Away pages, plus `data-year` in every footer |
| Canonical / OG URLs | every page `<head>`, currently relative so they work on any host |
| Sitemap domain | `sitemap.xml` and `robots.txt` — `https://example.com` |

Two placeholders need a note because they are not obvious:

**The running chart** in `away/index.html` is hand-drawn SVG, not generated.
Twelve `<rect>` elements each carry the month: `height` is the value and `y` is
`232 - height`. The heights currently in the file are a template drawing and do
not correspond to any real data. Change `height` and `y` together, update the
axis numbers in the `chart__axis` group and the `<title>` for screen readers,
and delete the slot above the chart when the numbers are real.

**The `aria-label` on a table scroll region** names the table's contents, so it
has to change when the table does — search `table-scroll`.

### Replacing the plates with photographs

Every image slot already points at a real path. The pattern is:

```html
<a class="plate" href="/assets/img/plates/plate-arcs.svg" data-lightbox>
  <img src="/assets/img/plates/plate-arcs.svg" alt="…" width="800" height="600">
</a>
```

Drop a JPEG or WebP into `assets/img/` and change the two paths. Keep the
`width` and `height` attributes accurate — they are what stop the layout
shifting while images load. Keep `alt` descriptive; the lightbox copies it
into the overlay caption.

The `.plate` frame (paper mat, hairline border, two registration marks at
opposing corners) is applied in CSS, so any image inherits the house style.
`.project-card__media img` uses `mix-blend-mode: multiply`, which sits a
photograph into the paper ground; remove that one declaration if your images
come out muddy.

### Adding or removing a slot

The site ships with two project slots and one research slot. There is no reason
to keep three — the number is just how many blocks are in the source.

To **add** one:

1. Copy `projects/project-01/` to a new folder and edit it. `.case-hero`,
   `.prose--case`, `.pager` and `.footnotes` are the whole template.
2. Copy one `<li class="entry entry--slot">` block in `projects/index.html`
   (or the `research` equivalent) and give it a matching `id`.
3. Add it to the home page's work grid or research list.
4. Add it to the footer's "Write-ups" column on every page — the footer is
   duplicated per page, since there is no templating engine.
5. Add it to `sitemap.xml`.

To **remove** one, do the reverse: delete the folder, then the entry, the card,
the three footer links and the sitemap entry. Anything you miss shows up as a
404 in the link crawl below.

## Fonts

Fraunces (variable: `opsz`, `wght`, `SOFT`, `WONK`), Manrope (variable:
`wght`) and IBM Plex Mono (400, 500). All SIL Open Font License 1.1.

```bash
bash tools/fetch-fonts.sh   # re-downloads, keeps latin + latin-ext only
```

`tools/fetch-fonts.sh` pulls the Google Fonts CSS with a modern browser user
agent, keeps only the `latin` and `latin-ext` blocks, downloads each `woff2`
and rewrites the `src` URLs to `../fonts/`. It regenerates
`assets/css/fonts.css` wholesale — do not hand-edit that file.

Only the two `latin` files are preloaded (`<link rel="preload">` on every
page). The `latin-ext` subsets are delivered but never fetched unless a page
uses a character in that range.

`base.css` declares three metric-override fallback faces (`Fraunces
Fallback`, `Manrope Fallback`, `IBM Plex Mono Fallback`) with `size-adjust`
and ascent/descent overrides. Those numbers are hand-tuned approximations, so
they reduce layout shift rather than eliminating it.

To swap the display serif, change `--font-display` in `tokens.css`. The
`WONK` axis is what gives the large headings their wonky `f` and `g`; a
different family may not have it, in which case drop the
`font-variation-settings` declarations in `base.css`.

## JavaScript

`assets/js/site.js` is enhancement only. Every page is complete without it:
the nav is a plain link list, figures are real links, the chart ships fully
drawn, and all content is in the HTML source. Six isolated functions
(mobile nav, reveal-on-scroll, chart draw-in, lightbox, copy-to-clipboard,
year stamp) each fail silently on their own.

One detail worth preserving: `.reveal-ready` is added **by the script**, so a
JavaScript failure can never leave content invisible. If you add
`data-reveal` to something, that is the only contract to know.

## Accessibility

- Semantic landmarks (`banner`, `main`, `contentinfo`, `nav` with labels),
  one `h1` per page, no skipped heading levels.
- Skip link is the first focusable element on every page.
- `:focus-visible` rings at 2 px in `--focus-ring`, offset 2 px.
- The lightbox is a labelled `role="dialog"` with `aria-modal`, closes on
  Escape, on backdrop click and on the close button, and returns focus.
- The copy button reports through a `role="status" aria-live="polite"` node.
- Every animation is inside `@media (prefers-reduced-motion: no-preference)`,
  and the reduced-motion block is a genuine off switch.
- Contrast is audited by walking rendered text nodes; the method and results
  are in the section below.

Two known soft spots, stated rather than hidden:

- `--mark` (`#9E6448`) and `--ochre` (`#A98443`) are for small marks, rules
  and labels only. Both are below 4.5:1 on paper, which is fine for
  non-text marks and large text but **not** for body copy. If you use them for
  running text, darken them first.
- The hiked-places table has no `<caption>`-level description of the data
  beyond the column headers, which is adequate but not generous.

These are the checks that were run against this build. They use the preview
browser's own engine, so the numbers are real computed values rather than
claims.

| Sidenote float at ≥74 rem | the margin aside sits 32 px clear of the prose column; no line shortened |

Two notes on how to read the numbers above, since two of them were wrong in
earlier drafts of this file. The target count is **35**, not the 38 first
written here and not the 40 before that: one `url()` pattern was matching the
`data:` grain texture, and a second was matching the `url(#n)` filter
reference nested *inside* that data URI. Neither is a network fetch, and
removing both leaves 35 real paths. The contrast audit was re-run after the
placeholder rebuild, so the per-page counts above come from the pages as they
now ship rather than from the invented-content build. Six tokens are declared
in the scale but not yet referenced: that is a complete type/spacing/depth
scale being documented ahead of the rules that will use it, not unreachable
code.

Three real defects were found by these checks and fixed at the cause, rather
than by the checks being relaxed:

1. **Thirteen text styles failed 4.5:1.** The cause was three shared tokens —
   `--ink-500`, `--terracotta` and `--olive` — being light enough for
   decoration and being used for small text. All three were darkened in
   `tokens.css`, and the matching hard-coded values in the motif and plate
   SVGs were updated in step so the graphics did not drift lighter than the
   type.
2. **The document scrolled sideways at 390 px.** Two causes: `data-table`
   cannot shrink below its cells' min-content width, and grid tracks with the
   implicit `auto` size grow to fit min-content regardless of their
   container. Fixed with the `.table-scroll` region (focusable, so the scroll
   is keyboard-reachable) and with `minmax(0, 1fr)` plus `min-width: 0` on
   every layout grid.
3. **Every `.fill` inside a spec table rendered as ordinary ink.** `.spec dd`
   (specificity 0,1,1) beat `.fill` (0,1,0), so the marker silently lost its
   terracotta colour and dashed underline — a placeholder that no longer
   looked like one. Rather than adding a `.spec .fill` override that the next
   component would also have needed, the marker selector is now `.fill.fill`:
   doubled deliberately, so its specificity is (0,2,0) and it wins wherever
   it lands. Measured after the fix: `rgb(126, 77, 54)`, 6.31:1.

### Commands

```bash
# 1. server responds before anything else is trusted
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:4173/

# 2. every asset resolves with the right content type
for u in /assets/css/tokens.css /assets/fonts/fraunces-300-700-latin.woff2; do
  curl -s -o /dev/null -w "%{http_code} %{content_type} $u\n" "http://localhost:4173$u"
done

# 3. a missing path is a real 404, and serves 404.html
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:4173/no-such-page
```

In the browser panel (`/assets/js`-free):

- **Fonts actually loaded** — `document.fonts.check('16px Fraunces')` and
  friends, which proves the `@font-face` URLs resolve rather than merely
  that the CSS parsed.
- **Contrast audit** — walks text nodes, computes WCAG relative luminance
  against the effective background, and lists every pair under 4.5:1 for
  body text or 3:1 for large text and interactive marks.
- **Link crawl** — fetches every internal `href` and reports non-200s.
- **Page weight** — `performance.getEntriesByType('resource')`, summed.
- **Accessibility tree** — landmarks, heading order, `alt` presence.

**Not verified, and why:**

- **Print output.** Chromium's print emulation is not exposed to the browser
  tooling here, so `print.css` was checked by reading it and by confirming it
  parses, not by rendering a PDF. Open the print dialog and check a case study
  before you rely on it.
- **No-JS rendering.** There is no way to disable JavaScript in the preview
  panel, so this was verified by reading the HTML source: all content is in
  the markup and `site.js` only adds behaviour.
- **External citations.** There are none left to check. The research write-up
  now has a placeholder where its reference list was, so the site makes no
  outbound link that could rot. When you add real references, check them with
  `curl -I` before publishing — a 200 means the host serves the page to curl,
  which does not guarantee the anchor inside it stays put.

## Deploying

Static files, so any host works. Upload the repository root, excluding
`tools/` (it is a development-only helper) and `.freebuff/`.

Before deploying:

1. Replace the domain in `sitemap.xml` and `robots.txt`.
2. Replace the placeholder email and social links in `contact/index.html`.
3. Replace the canonical and `og:url` values if you want absolute URLs — they
   are currently relative paths, which work but are weaker for social cards.
4. Confirm the host serves `404.html` for unknown paths with a 404 status,
   and resolves `/projects/` to `projects/index.html`. If it does not, add a
   redirect rule or rename the folders to `projects.html` and fix the links.

Nothing here needs a server, a database or a secret.
